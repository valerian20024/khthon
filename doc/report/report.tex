\section{Introduction}

We will first give an overview of the project before moving into more details.

The compiler is named Khthon: derived from the greek $\chi\theta o \nu \iota o \zeta$ ("khthonios"), meaning "from the ground", metaphorically transforming high level language to a more ground-based IR. 

The git repository \footnote{\url{https://github.com/valerian20024/khthon}} is also available. There is much more in it than the sole source code and report posted on the submission platform.

A Doxygen documentation is given with the source code, though it might not be complete.

I have attended the course in 2024-2025, which allowed me to get some experience with the 3 first steps. I decided to do the project alone this year because I have had some troubles in my team work last year and I thought I could reuse some parts to have a quick start. 

As of \textcolor{red}{10 May 2026}, the project state can be summarized using VSCodeCounter's\footnote{\url{https://marketplace.visualstudio.com/items?itemName=uctakeoff.vscode-counter}} output: \textcolor{red}{23 files,  4257 codes, 639 comments, 1082 blanks, all 5978 lines}

Unfortunately, I cannot state precisely how much time I have passed on the project, but I estimate it to be about $200$ hours, all in all. While that may seem a lot, it is mainly because I have used this project as an experimenting ground for learning C++. I was also quite passionate about it and willing to do it right. I have put some effort into readibility, architecture and correctness. While it may not be perfect since this is still the first actual C++ project I have tackled, I clearly feel I have improved my skills with this project.

\subsection{Semantic Analysis}

Decided to incorporate small duplicate checks inside the ClassesVisitor for an early stopping.
If the class has been defines several times, there's likely a big problem, so the compiler won't take the time to inspect every fields and methods inside it, which could potentially be all duplicated. 
We simply tell it is duplicated and return early, not adding this class to the symbol table for further inspections.

\section{Potential improvements}
Now that I have more experience both in compiler design and in C++, there are many things I would like to improve, most notably:

\begin{enumerate}
    \item Change the lexer to only take one keyword token and use a hash table to decide its content.
    \item Create a dedicated \texttt{ErrorLogger} instead of putting the responsibility of error management to \texttt{Driver}. The errors could be more descriptive as well, copying the line from the source file to indicate the user where it happened. Using Bison's \texttt{location} to clearly highlight the error.
    \item Create some namespaces. As the code grew, \texttt{khthon::Type} is conflicting with \texttt{llvm::Type}. It would be a good time to start splitting into namespaces.
    \item Push further the Debug mechanics when compiling to have accurate and clean logging of what's happening. For now it's a bit mingled and not standardized.
    \item More consistent use of C++ features, such as move semantics.
    \item Clearly separating interface and implementation, even when having trivial methods, for example in \texttt{ast.hpp}.
    \item \texttt{Driver::print\_diagnostics} should print them in order (line, column) when compiling in release mode and keep the original order when compiling in Debug mode.
\end{enumerate}

This project will outlive the scope of this course and I shall improve Khthon in my free time.
