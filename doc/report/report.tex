\section{Introduction}

The compiler is named Khthon: derived from the greek $\chi\theta o \nu \iota o \zeta$ ("khthonios"), meaning "from the ground", metaphorically to transform high level language to a more ground-based IR. 

The git repository \footnote{\url{https://github.com/valerian20024/khthon}} is also available for more extensive investigation. 

A Doxygen documentation is given with the source code, though it might not be complete.

\subsection{Semantic Analysis}

Decided to incorporate small duplicate checks inside the ClassesVisitor for an early stopping.
If the class has been defines several times, there's likely a big problem, so the compiler won't take the time to inspect every fields and methods inside it, which could potentially be all duplicated. 
We simply tell it is duplicated and return early, not adding this class to the symbol table for further inspections.

\section{Potential improvements}
Now that I have more experience both in compiler design and in C++, there are many things I would like to improve, most notably:

\begin{enumerate}
    \item Change the lexer to only take one keyword token and use a hash table to decide its content.
    \item Create a dedicated ErrorLogger instead of putting the responsibility of error related mechanics to Driver.
    \item Create some namespaces because the code gets quite big now, and Khthon::Type is conflicting with llvm::Type.
    \item Push further the Debug mechanics when compiling to have accurate and clean logging of what's happening. For now it's a bit mingled and not standardized.
    \item More consistent use of C++ features, such as move semantics.
\end{enumerate}
